# Conservative integration of arXiv 2510.04963 in MixingModel

The default implementation retains the full published 18-dimensional Run-2 CP-violating Gaussian and replaces the old inclusive `UID19` constraint with two correlated hadronic summary approximations. Their weights sum to one to account conservatively for their unknown mutual correlations. The standalone `UID18` Run-1 term is omitted. This version requires no external threshold-likelihood package and preserves every parameter index of the supplied Run-2 implementation.

This is an explicitly approximate combination. It does not reconstruct the original CLEO/BESIII event likelihoods or remove the external priors already embedded in their fitted summaries. The covariance bound below concerns the two adopted hadronic Gaussian blocks; it is not a guarantee of conservative uncertainty for the entire nonlinear global fit.

## Likelihood included by default

With fixed weight `w = 0.5`, the added log likelihood is

```text
log L = log L_other
      + log L_Run2_18D
      + w       * log G_inclusive_4D
      + (1 - w) * log G_binned_8D.
```

`L_other` includes the existing charm and beauty measurements, including the existing BESIII branching-ratio measurements. It excludes `UID19` and `UID18` in this mode. No separate full Run-1 K3pi term is introduced. No interpreted Run-2 result from Tables 8 or 9 of 2510.04963 is added.

The Run-2 central values, statistical errors, systematic errors and both 18 by 18 correlation matrices are unchanged from the supplied patch. Its predictions remain

```text
x+ = xcp + dx;    y+ = ycp + dy;
x- = xcp - dx;    y- = ycp - dy;
Q+/- = (x+/-)^2 + (y+/-)^2;
(kappa y'+/-)_i = kappa_i * (y+/- cos(delta_i) - x+/- sin(delta_i));
r_i+ = r_i- = r_i, because the model assumes AD = 0.
```

The `r_i` are amplitude ratios, not squared ratios. Phases are stored in radians. This retains the measurement-level construction described in [2510.04963, Section 8 and Appendix A](https://arxiv.org/html/2510.04963v2).

## Hadronic summaries and numerical choices

The source is [2103.05988v3, Appendix C](https://arxiv.org/html/2103.05988#A3). The inclusive block uses the **BESIII and CLEO-c** column of Table 18 and the corresponding Table 19 correlation matrix. The binned block uses Tables 21 and 22. The explicitly LHCb-combined inclusive column and Table 20 are excluded from the default mode.

The inclusive vector is ordered as

```text
(kappa_K3pi, delta_K3pi, kappa_Kpipi0, delta_Kpipi0).
```

Its Gaussian inputs are:

| Quantity | Central value | Default Gaussian sigma |
| --- | ---: | ---: |
| Inclusive kappa_K3pi | 0.49 | 0.105 |
| Inclusive delta_K3pi | 154 degrees | 18 degrees |
| kappa_Kpipi0 | 0.79 | 0.04 |
| delta_Kpipi0 | 196 degrees | 11 degrees |

The correlation matrix in this order is

```text
 1.00  -0.78   0.04  -0.07
-0.78   1.00   0.15  -0.15
 0.04   0.15   1.00   0.23
-0.07  -0.15   0.23   1.00
```

This is a covariance submatrix of the full six-parameter result. Taking a covariance submatrix gives the marginal Gaussian for the retained coordinates; it does not fix the omitted amplitude ratios. Taking a submatrix of the precision matrix would instead condition on the omitted coordinates and would be incorrect here.

The binned vector alternates coherence and phase:

```text
(kappa_1, delta_1, kappa_2, delta_2,
 kappa_3, delta_3, kappa_4, delta_4).
```

| Bin | kappa | Default sigma for kappa | delta | Default sigma for delta |
| --- | ---: | ---: | ---: | ---: |
| 1 | 0.66 | 0.195 | 117 degrees | 11.5 degrees |
| 2 | 0.85 | 0.175 | 145 degrees | 18.5 degrees |
| 3 | 0.78 | 0.120 | 160 degrees | 19.5 degrees |
| 4 | 0.25 | 0.205 | 288 degrees | 22 degrees |

The complete published eight-parameter correlation matrix is implemented, including correlations between bins. Its entries were checked against the arXiv TeX source of Table 22. Table 21 in that source prints the first phase uncertainty as `+14/-9` degrees; the default sigma above follows those printed numbers explicitly.

For asymmetric errors the default prescription is

```text
sigma = (sigma_lower + sigma_upper) / 2.
```

`K3piSummaryErrors::LargerSide` instead uses the larger quoted side. This is a sensitivity prescription, not a reconstruction of the non-Gaussian likelihood and not a theorem that every resulting correlated contour is wider than the default contour. The published correlation coefficients remain unchanged under either prescription.

Gaussian phase residuals are wrapped to the interval from minus pi to pi around each quoted mean. Coherence factors retain their existing physical prior range from zero to one. The phase treatment is a local Gaussian approximation on periodic coordinates; it is not an exact wrapped multivariate distribution in the far tails.

## Why the amplitude ratio constraints are omitted

The new Run-2 measurement already constrains all four binned amplitude ratios. The existing model also contains branching-ratio measurements for the inclusive decay modes. Adding the hadronic summaries' amplitude-ratio constraints separately would require correlations with the retained coherence and phase coordinates that are not all published for the binned result.

The implementation therefore uses the available 4D and 8D marginals and adds no additional Gaussian on the summary values of the amplitude ratios. Their current model priors and existing branching-ratio likelihoods remain in place. This reduces explicit reuse of the normalisation information. It does not undo the influence those inputs had on the fitted coherence and phase summaries.

## Bound for the unknown cross covariance

The inclusive and binned summaries reuse threshold events and external inputs. Their joint cross-covariance is unavailable. Multiplying their unmodified Gaussian likelihoods as independent factors would assign unjustified precision.

Let `A` and `B` be the adopted marginal covariances, and let `X` be any cross-covariance for which the joint matrix is positive semidefinite:

```text
J = [ A    X  ].
    [ X^T  B  ]
```

Use the inflated block covariance

```text
D_w = diag(A / w, B / (1 - w)),       0 < w < 1.
```

Set

```text
S = diag(sqrt((1-w)/w) I, -sqrt(w/(1-w)) I).
```

Then

```text
D_w - J = S J S^T >= 0.
```

Thus `D_w` bounds every admissible joint covariance with the chosen marginals. For positive-definite matrices this also implies `D_w^-1 <= J^-1`: the Gaussian quadratic penalty cannot be stronger than that obtained with any such true joint covariance. At equal weights the covariance of each block is doubled, or its standard deviations are multiplied by the square root of two.

The equivalent implementation is

```text
chi2_had = w * chi2_inclusive + (1-w) * chi2_binned.
```

The factors are weighted once, at the log-likelihood evaluation. The stored marginal covariance matrices are not also inflated, which would apply the weakening twice. At fixed weights the difference in Gaussian normalisation is independent of the fit parameters and does not affect their posterior shape. The weights are constructor settings, never sampled fit parameters or adjusted at individual likelihood points.

Equal weights give a transparent balanced choice. They are not claimed to optimise information for every observable. Fixed values such as 0.25 and 0.75 allow a robustness study. The underlying approach is related to [covariance intersection for unknown correlations](https://isas.iar.kit.edu/pdf/SPL15_Reinhardt.pdf); the block-matrix proof above establishes the bound used here directly.

The mathematical statement assumes that `A` and `B` adequately describe the Gaussian summaries. It does not validate Gaussian approximations to bounded, asymmetric hadronic likelihoods, establish Bayesian coverage after nonlinear transformations, or bound correlations with data outside these two blocks.

## Run 1 and the inclusive parameters

The original `UID19` represented an inclusive threshold plus LHCb combination, while `UID18` added the Run-1 quadratic observable separately. The default mode removes both factors and uses the explicitly threshold-combined summaries above. A full Run-1 direct likelihood is not restored because normalisation and mixing inputs remain embedded in the hadronic summaries, so independence could not be established.

The inclusive parameters `rD_k3pi`, `dD_k3pi`, `kD_k3pi` remain independent sampled coordinates used by the existing inclusive charm and beauty likelihoods. The bin parameters are separate effective coordinates for the four-bin region. No identity between the inclusive parameters and four-bin moments is imposed. This is a relaxation of the physical relation, with some loss of information, rather than an assumed extrapolation.

The four bins exclude a region around the Ks mass. Consequently, a numerical moment relation would need the CF bin fractions and a treatment of that excluded region appropriate to each inclusive measurement. Neither those fractions nor an uncertainty or correction for the excluded region is invented here. The default approximation retains useful inclusive and binned constraints without forcing an unsupported map between them.

## Reference mode and sensitivity settings

Existing calls select the new default without changing the calling code:

```cpp
MixingModel model(variables, combination);
```

The reference uses the original numerical `UID19` Gaussian and only the Run-2 quadratic marginal:

```cpp
MixingModel reference(variablesWithoutBinHistograms, combination,
    MixingModel::K3piInputMode::QuadraticReference);
```

It also removes `UID18`. It does not define the twelve bin parameters or add either new threshold summary. Bin histogram requests are rejected in this mode. The original `UID19` numbers are retained exactly for comparison, rather than silently correcting or substituting its original approximation.

The Run-2 reference mean is `(6.1e-5, 6.8e-5)`, with covariance

```text
V_Q = 1e-9 * [ 1.933     -0.032096 ].
             [-0.032096   1.933    ]
```

This is the covariance submatrix for entries zero and nine of the 18D Gaussian, reconstructed from its separate statistical and systematic inputs. It integrates out the other measured coordinates within that Gaussian approximation; it does not condition them on their central values. Its predictions are `(xcp+dx)^2+(ycp+dy)^2` and `(xcp-dx)^2+(ycp-dy)^2`.

For a combined weighting and error sensitivity test, for example:

```cpp
MixingModel alternative(variables, combination,
    MixingModel::K3piInputMode::ConservativeSummaries,
    0.25,
    MixingModel::K3piSummaryErrors::LargerSide);
```

The reference and default differ in both the hadronic constraints and the Run-2 information retained. Their posterior difference must therefore not be attributed solely to the linear Run-2 observables.

## Remaining correlations and validation limits

The hadronic summaries inherit constraints on mixing, two-body hadronic parameters and branching fractions. Some of those inputs also occur in the global model. Omitting the ratio coordinates and the standalone Run-1 factor reduces explicit reuse but does not perform an exact prior subtraction. The unknown cross-covariance bound covers the two hadronic summary blocks only.

The Run-2 CPV measurement also uses external asymmetry corrections related to `a_d(KK)` and `Delta Y`. Their residual overlap with global CPV information remains. A profiled 18D covariance does not expose the information needed to remove it exactly.

These approximations mean that agreement with the paper's interpreted Table 9 is not an acceptance criterion. A posterior sensitivity study should compare the default, fixed alternative weights, the larger-side error prescription, and the quadratic reference. No full MCMC posterior comparison or reproduction of Table 9 has been performed for this revision.

## Checks and patch bases

The revised model and the repository main executable compile and link against the installed ROOT 6.40.04 and BAT setup. An MPI-initialised validation harness evaluates both modes for all five combinations. It checks that the total likelihood difference from the supplied source is exactly the replacement of the intended factors, verifies the unchanged 18D covariance and central values, verifies the 2D marginal covariance, tests phase periodicity and rejects invalid configuration and parameter-vector sizes. All 13,111 runtime checks pass.

The installed BAT is the parallel build. The updated launcher now initialises MPI before constructing the model. The scientific validation harness also initialises MPI explicitly. The MPI launcher changes and their separate startup tests are described below.

Both new correlation matrices are positive definite. The static audit checks all parameter names and assignments, checks the binned correlation entries against the published TeX, and verifies both patches by dry run and by actual application followed by byte comparison. The analytic covariance bound is also exercised numerically with 300 admissible cross-covariances; these numerical checks supplement the proof rather than replace it.

`2510.04963_MixingModel_followup.patch` applies to the supplied already-patched files copied from the local repository. `2510.04963_MixingModel_summary.patch` includes the original Run-2 integration and applies to the public repository baseline at commit `404ed749873311ffc07d5a504c4c0da1c28dbf1e`. The baseline blobs are `7225a844ee3b608a62f503a86997edd81d484f81` for the source and `5afec3e25435c9d2c3d5d0ed7037ee09440e26c3` for the header. Both combined patches now include `Codes/main.cpp`, `CMakeLists.txt` and `compile_main.sh` as well as the two model files. Choose the combined patch matching the starting version and apply it once. `2510.04963_MPI_launcher.patch` is an alternative containing only the launcher and build changes, for a checkout where the earlier scientific revision has already been applied.

The output files were generated separately. The user's repository files were not overwritten. `validation-summary.json` records the source hashes, covariance checks and patch checks.

## MPI launcher initialisation and shutdown

The parallel BAT library calls `MPI_Comm_size` during model construction. `Codes/main.cpp` now calls `MPI_Init_thread` before any model is constructed, requests `MPI_THREAD_FUNNELED`, and checks that the supplied thread support is sufficient. An automatic-lifetime object keeps MPI active until the model and ROOT output objects have been destroyed, then calls `MPI_Finalize`. Exceptions from model setup or fitting are reported with a failure exit status after stack unwinding and MPI shutdown. The help path exits before MPI is initialised because it constructs no BAT objects. These lifecycle requirements follow the [Open MPI documentation](https://docs.open-mpi.org/en/main/man-openmpi/man3/MPI_Init_thread.3.html).

This fix preserves the existing single-process command-line invocation. A launch with more than one MPI process is rejected before any fit or output directory is created. The installed parallel BAT source uses scatter/gather commands that require an application-side worker loop on additional ranks; initialisation alone does not implement that loop. Distributed likelihood evaluation is outside this launcher fix.

`CMakeLists.txt` now discovers the MPI C++ component and links `MPI::MPI_CXX`. MPI development headers and libraries must be available from the same compatible MPI installation used by BAT. `compile_main.sh` keeps its six arguments but delegates compilation to CMake, which correctly handles quoted ROOT/BAT flags. It preserves the `main.x` output executable and exits immediately on a failed configuration or build. A separate `compile_classes.sh` invocation is unnecessary when using this updated launcher script.

The script reuses the repository's `build` directory by default. `GAMMADDBAR_BUILD_DIR` selects another build directory; `MPICXX` selects an MPI compiler wrapper. A previously configured build directory retains its `ROOT_CONFIG_DIR` and `BAT_CONFIG_DIR`. A fresh CMake build can be configured explicitly, for example:

```sh
cmake -S . -B build \
  -DROOT_CONFIG_DIR=/opt/homebrew/bin \
  -DBAT_CONFIG_DIR=/Users/silvest/Documents/GitHub/HEPfit/BAT_parallel/bin
cmake --build build
```

The launcher was tested through both CMake and the shell script with two chains, a maximum of sixteen pre-run iterations and eight sampling iterations. Both short runs exited successfully and wrote ROOT output. These are startup and shutdown smoke tests, not converged scientific fits. The checks also cover help, invalid model configuration, rejection of a two-process launch, shell argument validation, and preventing execution of a stale binary after a failed build. `mpi-validation-summary.json` records the outcomes.
